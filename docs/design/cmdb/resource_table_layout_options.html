留白过大 横向滚动 表头对比偏弱 身份层级不清

问题来源

  • 表格用 fill 撑满工作区，2 行数据下方留下大片玻璃背景。
  • UUID 与长名称没有列宽上限，自动布局把表格撑宽。
  • 表头 11px 大写 + 低透明度，行分隔与悬停也很轻。
  • 四个操作图标同时着色，视觉噪音高于数据本身。

适合

作为基线对照。除非只想确认现状，不建议原样保留。

目标

不改变操作习惯，只让表格更稳、更快读。这是改动量和收益最平衡的一版。

关键改动

  • 身份列前置：名称优先，UUID 缩略为可复制的短 ID。
  • 表头吸顶、去掉大写字母间距，提高对比度。
  • 行高压缩到 36–40px，名称加粗，其余列降级。
  • 次要列限宽 + 截断 + 悬浮完整值，常见宽度不再横向滚动。
  • 表格改近实色表面，玻璃只保留在页面外壳。
  • 操作图标中性色，悬停才着色；删除仅悬停变红。
  • 少量数据时表格高度随内容，不再撑满全屏留白。

代价与适合

中等 CSS/组件调整。列顺序改为“名称优先”，需要确认与字段配置的优先级。适合日常浏览、少量编辑和大多数资源模型。

目标

用最小的改动先解决“看不清”的问题，布局与交互保持现状。

关键改动

  • 表格表面从半透明玻璃改为近实色面板。
  • 表头更亮、去掉大写字母间距，行分隔和悬停更清晰。
  • 操作图标改为中性色，悬停才着色。
  • Liquid Glass 只保留在页面外壳与侧栏。

代价与适合

最小改动、最低风险。但大片留白、横向滚动、身份层级问题都不解决。适合先快速提升可读性，后续再动布局。

目标

为资源量大、频繁扫读和编辑的场景服务。密度、固定列和响应式收列是重点。

关键改动

  • 表头吸顶，身份列横向吸附，操作列固定在右侧。
  • 名称 + 短 ID 双行身份单元格，信息更集中。
  • 紧凑 / 舒适密度切换，按操作员偏好持久化。
  • 窄屏自动收起次要列，完整内容仍在侧栏。
  • 多个行操作收进“⋯”菜单，减少图标噪音。

代价与适合

中等改动。固定列、密度切换和窄屏收列都需要真实浏览器回归。适合资源数量大、操作频繁的团队。

目标

字段少、以浏览和进入详情为主时，让每一台资源都容易读、容易点。

关键改动

  • 默认展示资源卡片：名称、状态、短 ID 与 2–3 个关键字段。
  • 点击卡片打开现有详情抽屉；操作按钮保留在卡片底部。
  • 表格保留为“明细”视图，供需要多列对比的操作员切换。
  • 宽屏两列、窄屏单列，卡片高度由内容决定。

代价与适合

改动最大，多列对比能力下降。适合字段少、以浏览和详情为主，或需要兼顾窄屏与触控的场景。

怎么选

只想快速改善观感选 B；兼顾布局与风险选 A；资源量大选 C；字段少、以详情为主选 D。
