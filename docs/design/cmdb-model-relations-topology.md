# CMDB 模型关系拓扑重设计

日期：2026-10-30
状态：已实现（2026-10-30）

## 背景与目标

模型详情页的「模型关系」标签目前用共享 `TopologyGraph` 画一跳星形图：节点是统一的中性色卡片，边是直角虚线，没有悬停聚焦、折叠下钻、全屏或导出。节点一多就显得拥挤，也很难顺着 `contain` 关系继续往下看。

本次重设计只针对这一处拓扑，目标是：

- 当前模型始终是视觉与层级中心，入边在左、出边在右，方向一眼可读；
- 节点采用玻璃卡片、按模型分组着色，连线和标签清晰、互不穿透；
- 悬停时聚焦直接关联路径，其余内容降透明；
- 可以沿远离中心的方向按需展开下一层，折叠后显示隐藏数量；
- 提供居中、缩放、全屏、迷你地图和 PNG 导出。

## 已确认的视觉决策

来自 2026-10-30 的浏览器对比（`.superpowers/brainstorm/311887-1793339527/`）：

1. **布局 A：左右分层树**。中心模型居中，入边（父模型/依赖源）向左展开，出边（子模型/包含下级）向右展开。
2. **配色 A：分组语义色**。按管理员维护的共享模型分组取色；中心模型固定品牌靛蓝；未分组模型回退中性灰蓝。
3. **展开提示 B：右上角圆形徽标**。未加载时显示 `+`，加载中显示转圈，展开后显示 `−`，折叠后显示 `+N`（已知隐藏后代数）。

## 非目标

- 不修改后端 API、数据库或模型关系数据；
- 不改变其他页面的拓扑（`src/pages/Topology.tsx`、TopologyViews 等保持现状）；
- 不在图上新增/删除关系（沿用标签内现有的「加子模型 / 加父模型 / 删除」）；
- 不持久化展开状态、节点拖动位置或缩放位置；
- 不追求一次加载整个模型关系图。

## 数据与 API

沿用现有接口，不新增：

- `listCITypes()`：模型别名、标识、图标；
- `listModelGroups()`（`/preferences/model-groups`，管理员维护的共享分组）：模型 → 分组；
- `relationParents(ref)` / `relationChildren(ref)`：一跳关系，含关系类型、约束、`ctr_id`。

初始加载：中心模型的父、子各一跳，与现在一致。

按需展开：只沿**远离中心**的方向取下一层。

- 左侧节点（入边侧）展开时请求它的 `relationParents`，继续向左；
- 右侧节点（出边侧）展开时请求它的 `relationChildren`，继续向右；
- 中心节点两侧各加载一跳，不提供「展开中心」。

这样既符合方向语义，也不会把兄弟节点或反向关系拉进画面。新建边统一为 `父模型 → 子模型`，与现有 `saveRelation` 的方向一致。

## 状态模型

纯函数放在 `web/src/cmdb/components/model-relations/model-topology.ts`，与 React 解耦：

```ts
type Side = 'center' | 'left' | 'right';

type TopologyNodeData = {
  id: number;              // 模型 id
  alias: string;
  name: string;
  icon?: string;
  groupColor: string;      // 分组语义色；未分组为中性色
  side: Side;
  depth: number;           // 距中心跳数
};

type TopologyEdgeData = {
  key: string;             // `${source}-${target}-${relationId}`
  source: number;          // 父模型
  target: number;          // 子模型
  relationName: string;
  relationColor: string;
  direction: 'in' | 'out';
};
```

状态由四部分组成：

- `nodes` / `edges`：已加载的完整图，包含被折叠隐藏的节点；
- `probe`：按 `${modelId}:${direction}` 缓存的下一层探测结果（`RelatedType[]` / 加载中 / 失败），用于在展开前算出真实 `+N`；
- `expanded`：已展开的模型 id 集合（中心始终包含）；
- `loading`：正在请求下一层的模型 id 集合。

可见图 = 从中心出发、沿远离中心方向遍历，只穿过 `expanded` 节点的 BFS 结果。跨边只保留两端都可见的边。

- 折叠：把节点移出 `expanded`，可见图据此缩小；`+N` 由完整图从该节点向下 BFS 得到。
- 重新展开：直接复用已加载节点，不重复请求。
- 加载失败：节点保持未展开，徽标恢复为 `+`，toast 报错并保留已有图。
- 防环：远离中心方向的遍历遇到已存在节点只补边、不再重复展开；指向中心方向的边不参与展开。
- 规模保护：可见节点超过 300 时停止展开并提示「节点过多，请先折叠部分分支」，避免一次拉爆画布。

### 多路径、双向关系与重复边

- **一个模型只对应一个节点**（React Flow 节点 id 直接用模型 id）。
- 节点的 `side` / `depth` 由从中心出发的 BFS 首次发现时决定，遍历顺序固定：中心父模型 → 中心子模型 → 各自向外。后续从另一侧或多条路径再次发现同一模型时，只补边，不改变它的 `side` / `depth`，也不再重复展开。
- 同一模型与中心同时存在两个方向的关系时（A→中心 且 中心→A），模型只出现一次：`side` 由先处理的方向决定（默认入边侧优先，即出现在左侧），两条边都渲染，反向边按下面的连接点规则绕行；反向边不参与后续展开。
- 折叠时 `+N` 按唯一模型 id 计数，重复路径不重复计数；只统计沿远离中心方向、从该节点可达且当前隐藏的节点。
- 边按 `父模型 → 子模型` 定向；连接点由两端实际 x 坐标决定（见「连线」），因此反向边也能正确指向。

## 布局

使用已依赖的 `@dagrejs/dagre`，`rankdir: 'LR'`：

- 节点尺寸：中心 190×64，普通节点 170×56；
- `nodesep: 44`，`ranksep: 120`，四周边距 40；
- 布局后整体平移，使中心节点位于坐标原点；左侧为负 x，右侧为正 x；
- 每次可见图变化后重新布局，并 `fitView({ padding: 0.18, duration: 300 })`；
- 顶部工具栏的「居中」调用 `fitView`；缩放范围 0.25–2.0。

节点不开启拖动（避免与画布平移、重新布局冲突）；画布支持滚轮缩放、拖拽平移、触控板捏合。

## 连线

- 使用三次贝塞尔曲线，不用直角折线；入边从左侧节点右缘连到中心左缘，出边从右缘连到右侧节点左缘。
- 边的连接点按两端实际坐标选择：目标在右则源用右缘、目标用左缘，目标在左则反过来。因此反向边（右侧模型指回左侧模型）会从卡片左侧出来、绕行连接到目标，箭头始终表达真实方向。
- 同一对模型存在多条关系时，每条关系各画一条边：按 `ctr_id` 升序排列，贝塞尔控制点按索引上下偏移 12px，最多错开 3 条；超过 3 条时只前 3 条显示标签，其余只画线。每条被标注的边都显示自己的关系类型，不合并成一条。
- 标签是带底色的胶囊：背景取页面底色，边框与文字取关系类型颜色（浅色主题下把颜色压暗到可读），保证线条不会穿过文字。
- 边颜色取 `relation_type.color`，缺失时用中性 `#94a3b8`。

## 节点卡片

- 圆角 12px、1px 边框、轻阴影；背景为 `.cmdb-liquid` 变量下的玻璃面板（`--liquid-panel` / `--liquid-border`），带 `backdrop-filter`。
- 左侧 3–4px 分组语义色竖条；左上角 28px 图标容器（`CMDBIcon`，分组色 12% 底）。
- 第一行模型别名（13px/600），第二行技术名（9–10px mono）；长文本截断并保留 `title`。
- 中心节点放大、边框加粗为品牌靛蓝并带轻微外发光，其余节点不使用发光。
- 右上角展开徽标：18px 圆形按钮，分组色底、白字；`aria-label` 说明「展开 N 个下级 / 收起 N 个下级」。点击徽标不触发节点跳转。
- 点击节点卡片跳转到该模型的模型关系标签（`/cmdb/models/{id}?tab=relations`），与现状一致。

### 分组语义色

- 调色板 6 色：蓝 `#3b82f6`、青 `#0ea5e9`、暖橙 `#f59e0b`、紫 `#8b5cf6`、绿 `#10b981`、玫瑰 `#f43f5e`。
- 按 `listModelGroups()` 返回的管理员排序，为每个分组分配一个颜色；`is_other`（「其他」）和未分组模型用中性灰蓝 `#64748b`。
- 中心模型固定品牌靛蓝 `#6366f1`，不受分组影响。
- 分组重排会改变颜色；这是管理员可控的展示顺序，颜色只承担辅助区分，不承载必须记住的语义。
- **这是本次的默认取舍**：不使用分组名关键字匹配（如「人员」→暖色），以免中英文命名差异导致不可预期的跳色。如需要固定映射，可在实现前追加一张「分组名 → 色」白名单。

## 交互

- **悬停/聚焦**：悬停或键盘聚焦某节点时，计算直接相连的边与邻居节点，保持 100% 不透明；其余节点、边、标签降到 18%，过渡 120ms。移出恢复。标签只对高亮路径保持显示。
- **展开前探测（悬停预取）**：非中心节点在鼠标悬停或键盘聚焦 200ms 后，按远离中心的方向请求下一层（左侧取 `relationParents`、右侧取 `relationChildren`），结果写入 `probe` 缓存。
  - 探测到 `N > 0`：徽标显示 `+N`；
  - 探测到 `N = 0`：不显示徽标，节点视为叶子；
  - 探测失败：保留一个淡化的 `+`，点击时重试并 toast；
  - 同一节点的探测只发一次，请求中不重复发；移出画布不取消已发出的请求，结果仍写入缓存。
- **折叠/展开**：点击徽标时优先使用 `probe` 缓存立即展开；尚未探测完成则等待完成（徽标转圈），不额外重复请求。展开后徽标为 `−`，折叠后显示 `+N`（已知隐藏后代数）。
- **触摸设备**：首次点击节点只聚焦并触发同样的高亮与探测，不打开模型；再次点击同一节点才跳转。鼠标单击保持直接跳转；点击徽标始终只做展开/折叠，不触发跳转。点击画布空白处清除聚焦。
- **画布控制**：滚轮缩放、拖拽平移、居中（fit view）。
- **全屏**：覆盖整个视口的浮层（`position: fixed; inset: 0`），保留顶部工具栏和关闭按钮；Esc 关闭，关闭后焦点回到触发按钮；全屏内是同一套图与交互。
- **导出 PNG**：导出当前视口（先 fit view），隐藏工具栏、迷你地图和悬停高亮后截图，文件名 `cmdb-<模型标识>-relations.png`；失败时 toast，不阻塞页面。需要新增轻量运行时依赖 `html-to-image`（约 40KB，React Flow 官方文档推荐的导出方式）。这是本设计唯一的新依赖。
- **迷你地图**：React Flow `MiniMap`，右上/右下可切换显示；小于 1024px 默认隐藏。

## 响应式与可访问性

- 画布高度：`h-[480px]`，`sm` 起 `h-[560px]`；全屏时占满视口。
- 小于 1024px：隐藏迷你地图；小于 640px：只显示当前聚焦路径的边标签，避免标签重叠；触摸设备通过首次点击聚焦即可看到这些标签。
- 工具栏按钮全部有 `aria-label` 与 `title`；徽标是真正的 `<button>`，支持键盘。
- 节点卡片 `tabIndex=0`，Enter 打开模型；聚焦等同于悬停，触发同样的高亮。
- 加载、空关系、请求失败分别有明确状态：空关系沿用现有 `EmptyStateCard`；失败给出可重试提示，不画成空图。

- **未知节点**：悬停/聚焦时懒加载下一层探测，显示真实 `+N`；无下级不显示徽标；点击徽标才展开并复用探测缓存。

- 同一模型只保留一个节点，反向边渲染但不参与展开。
- 导出当前视口；全屏为视口浮层；新增 `html-to-image`。
- 分组色按管理员排序分配；中心固定品牌靛蓝。
